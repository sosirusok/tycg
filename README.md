# 좀비고 거래소

좀비고 계정·클랜·굿즈 거래를 위한 한국어 거래 게시판입니다. 화면 구조는 숨고(soomgo.com)의 목록·프로필·채팅 흐름을 따르고, 메인 색은 파랑 `#0066FF` 한 가지만 씁니다.

**사이트 주소: <https://zhstrade.pages.dev>** (이전 주소 `https://zombiego-market.<계정 이름>.workers.dev`는 새 주소로 자동 이동)

- 거래 탭: **구매 · 판매 · 교환**
- 세부 분류: 구매·판매는 계정/클랜/굿즈 및 쿠폰/기타, 교환은 “[계정·클랜]에서 [계정·클랜] 구함”
- **대리 종료 (2026-10-22)**: 대리 게임과 그 알선은 게임산업진흥법 제32조 제1항 제11호로 금지되어 대리(구함)·대리(진행) 탭과 대리 인증을 없앴습니다. 마이그레이션 `0064_proxy_closed`가 기존 대리 글을 모두 숨기고(사유 `대리 카테고리 종료`, 작성자와 매니저만 열람·삭제 가능) 대기 중인 대리 인증 신청을 취소하며, 대리 게시판의 저장한 검색·알림과 대리 글에 대한 알림함 알림을 지우고, 채팅의 `문의한 글` 카드 제목을 `종료된 분류의 글`로 바꿉니다. 배포 중 예전 Worker가 쓴 대리 글은 매일 정리 때 같은 사유로 숨기고, 광고·자동 끌올 자리도 차지하지 못합니다. 공개 거래 기록에는 대리 거래의 제목이 나가지 않습니다(`종료된 분류의 거래`). 서버는 대리 글 작성·수정·끌올·광고와 대리 인증 신청·지급을 거부합니다(400 `대리 글은 더 이상 쓸 수 없습니다.`). 신고 사유에 `대리 게임·알선`이 있습니다.
- 판매: 즉거가·현젯(만원 단위), 즉거가를 바꾸면 이전 가격이 취소선으로 남음(예: ~~60만원~~ ~~50만원~~ 40만원)
- 구매: 최대 사용 가능 금액(MAX), 허용 대주 수, 전적 조건, 원하는 닉 조건
- 래더 시즌 체크(아이언 25~, 마스터 17~, 챔피언 8~, 나머지 6~현재 시즌), 우대 스킨, 대주 수, 팬텀 %, 닉 글자 수·등급으로 검색
- 네이버 로그인(30일 유지, 처음이면 닉네임만 정하면 가입), 프로필, 1:1 채팅(사진 첨부), 가격 제안, 찜, 신고, 차단
- **인증**: 본인 인증 · 신용인 · 중개 인증 · 가측 인증. 닉네임 옆에 인증 이름과 체크 표시
- **등급**: 일반 → 플러스 → 프리미엄 → 엘리트 → 관리자. 플러스 영구 3만원, 프리미엄 영구 5만원/6개월 3만원, 엘리트 영구 15만원/6개월 6만원, 관리자는 매니저 지정
- 인증·등급 신청: 우측 상단 **인증/등급 신청하기** → 설명 창 → **신청하러 가기** → 매니저와의 채팅. 매니저는 채팅의 신청 카드에서 바로 승인·반려하고, 오른쪽 회원 관리 패널에서 인증·등급을 지급·회수
- **중개/가측 탭**: 플러스 이상 등급(무료 체험 제외)의 회원이 중개 인증·가측 인증을 신청하고(중개 인증은 본인 인증도 필요), 매니저가 지급하면 헤더 오른쪽 위 '중개/가측' 탭에 나옵니다. 엘리트·관리자는 골드 카드(소개 25자)로 맨 위, 프리미엄은 큰 프로필(소개 12자), 플러스는 작은 프로필. 같은 등급 안에서는 접속 중인 회원 먼저, 그다음 3시간마다 바뀌는 무작위 순서입니다. 카드를 누르면 그 회원과의 채팅이 열리고 문의 양식이 입력창에 채워집니다. 거래 대금은 사이트를 거치지 않습니다.
- 매니저 관리: 신청, 회원 검색, 신고, 숨긴 글, 공지, 설정(등급 입금 안내 문구, 현재 래더 시즌)

결제·에스크로·거래 보증 기능은 없습니다. 중개·가측은 회원끼리 진행하며 사이트가 돈을 받거나 보관하지 않습니다. 등급 결제는 매니저 계좌 입금을 매니저가 확인한 뒤 지급하는 방식입니다.

## 서버 배포 (한 번만 설정)

서비스는 Cloudflare Workers(서버)와 D1(데이터베이스)에서 무료 요금제로 동작합니다. 저장소의 GitHub Actions가 데이터베이스 생성, 테이블 준비, 배포까지 모두 처리하므로 **로그인이나 명령어 입력 없이** 아래 두 가지만 한 번 등록하면 됩니다.

1. **Cloudflare API 토큰 만들기**
   1. <https://dash.cloudflare.com/sign-up> 에서 무료 가입(이미 있으면 로그인)
   2. <https://dash.cloudflare.com/profile/api-tokens> → **Create Token** → **Edit Cloudflare Workers** 템플릿의 **Use template**
   3. Permissions에 **+ Add more** → `Account` · `D1` · `Edit` 한 줄, `Account` · `Cloudflare Pages` · `Edit` 한 줄 추가(두 번째 줄은 새 주소 zhstrade.pages.dev용)
   4. Account Resources는 본인 계정 선택 → **Continue to summary** → **Create Token** → 표시된 토큰 복사
2. **GitHub 저장소에 비밀값 등록**: 저장소 **Settings → Secrets and variables → Actions → New repository secret**
   - `CLOUDFLARE_API_TOKEN`: 위에서 복사한 토큰
   - `MANAGER_PASSWORD` (**필수**, 8자 이상): 매니저 계정(아이디 `sosirusok`, 닉네임 `우와오`)의 비밀번호. 매니저 계정이 처음 만들어질 때만 쓰입니다. 매니저 계정이 없는데 이 값도 없으면 배포가 실패하고 안내가 남습니다(매니저가 없으면 인증/등급 신청을 받을 수 없음).
   - `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`: 네이버 로그인 값(아래 **네이버 로그인 설정**). 등록하면 배포 때 Worker 비밀값으로 넘어갑니다. 등록하지 않아도 Worker에 이미 있는 값(`wrangler secret put`으로 넣은 값)은 지우거나 비우지 않습니다.
3. **Actions → Deploy to Cloudflare → Run workflow** (이후에는 main 브랜치에 반영될 때마다 자동 배포)

실행 결과 요약(Summary)에 사이트 주소 `https://zhstrade.pages.dev`가 표시됩니다(그 이름을 다른 곳에서 이미 쓰고 있으면 Cloudflare가 붙인 `zhstrade-xxxx.pages.dev`). 처음 만든 주소는 연결까지 몇 분 걸릴 수 있습니다.

- 사진은 R2에 가입된 계정이면 R2에, 아니면 D1에 저장합니다. R2는 대시보드에서 별도 가입 절차가 필요하므로 켜지 않아도 됩니다. R2를 쓰지 않으려면 저장소 Variables에 `USE_R2`=`false`를 넣으세요.
- 토큰으로 볼 수 있는 Cloudflare 계정이 여러 개라면 `CLOUDFLARE_ACCOUNT_ID` 비밀값도 추가하세요.
- 원하는 workers.dev 주소 이름이 있으면 저장소 **Variables**에 `WORKERS_SUBDOMAIN`을 넣으세요. 개인 도메인은 Cloudflare Pages 프로젝트(`zhstrade`)의 **Custom domains**에서 연결합니다(Worker에 연결하면 이전 주소처럼 새 주소로 자동 이동됨).
- 비밀값이 없으면 배포 작업은 아무것도 바꾸지 않고 안내만 남깁니다.
- 웹 푸시(휴대폰 알림) 키는 배포가 처음 한 번 만들어 Worker 비밀값(`VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT`)으로 저장하고, 이후 배포에서는 그대로 둡니다. 따로 등록할 것은 없습니다. 키를 바꾸면 회원들이 알림을 다시 켜야 하므로 지우거나 바꾸지 마세요.

### 네이버 로그인 설정

회원은 네이버 계정으로만 가입·로그인합니다. 사이트 자체 아이디/비밀번호 가입과 로그인은 없어졌고(요청하면 410 `네이버 로그인으로 바뀌었습니다.`), 매니저 계정만 숨은 주소에서 비밀번호로 로그인합니다.

1. <https://developers.naver.com/apps/#/register> 에서 **애플리케이션 등록**
   - 애플리케이션 이름: `좀비고 거래소` (네이버 로그인 화면에 표시됨)
   - 사용 API: **네이버 로그인**. 제공 정보는 **회원이름**, **연락처 이메일 주소**, **출생연도**, **휴대전화번호** 4개를 모두 **필수**로 선택합니다. 사이트는 회원 구분용 `id`와 이 4개를 읽어 `users.pii`에 AES-GCM으로 암호화해 저장하고(키는 `PHONE_HASH_KEY`에서 HKDF로 만듦), 로그인할 때마다 새로 받은 값으로 바꿉니다. 휴대전화번호는 중복 가입 방지용 해시(`PHONE_HASH_KEY`로 서명)도 저장합니다. 별명·사진·성별·생일은 읽거나 저장하지 않습니다. 쓰는 곳: 본인 확인과 거래 분쟁 시 연락, 만 14세 미만 가입 제한(출생연도), 같은 번호 중복 가입 방지, 인증/등급 신청 확인
   - 환경: **PC 웹**과 **모바일 웹**
   - 서비스 URL: `https://zhstrade.pages.dev`
   - 네이버 로그인 Callback URL: `https://zhstrade.pages.dev/api/auth/naver/callback`
2. 등록 후 **Client ID**와 **Client Secret**을 저장소 비밀값 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`으로 등록하고 Actions에서 다시 배포합니다. Worker에 직접 넣었다면(`wrangler secret put NAVER_CLIENT_ID` 등) 등록하지 않아도 됩니다. 두 값이 없으면 로그인 창에 `네이버 로그인 설정이 아직 끝나지 않았습니다.`가 표시됩니다.
3. **검수 요청**: 등록 직후에는 '개발 중' 상태라 개발자센터의 **멤버관리**에 넣은 네이버 아이디만 로그인할 수 있습니다. 내 애플리케이션 → **네이버 로그인 검수 요청**에서 서비스 화면(로그인 창, 가입 마무리 화면)을 첨부해 검수를 받아야 모든 사람이 로그인할 수 있습니다.

- **가입 마무리**: 처음 로그인한 네이버 계정은 닉네임(기존 규칙: 중복·비슷한 닉네임 불가, 30일에 한 번 변경)을 정하고 이용 규칙 동의와 `만 14세 이상입니다`를 모두 체크하면 가입됩니다(서버도 `age14:true` 없이는 400 `만 14세 이상만 가입할 수 있습니다.`). 기존 계정 연결도 예전 가입 때 묻지 않았으므로 `만 14세 이상입니다`를 체크해야 연결됩니다(서버 400 `만 14세 이상만 이용할 수 있습니다.`). 플러스 7일 무료 체험과 같은 곳에서 가입한 계정 수 제한은 예전 가입과 같습니다.
- **기존 계정 연결**: 예전 아이디/비밀번호로 가입한 회원은 가입 마무리 화면의 **기존 계정 연결**에서 예전 아이디와 비밀번호를 한 번 입력하면 그 계정이 네이버 계정에 연결됩니다. 연결하면 예전 비밀번호는 지워집니다. 비밀번호를 잊은 회원에게는 매니저가 회원 관리의 **임시 비밀번호 발급**으로 연결용 비밀번호를 줄 수 있습니다(연결 전 회원에게만 표시).
- **매니저**: 저장소 비밀값 `MANAGER_PHONE`(매니저 휴대전화번호, 숫자만: `01012345678`)을 넣고 다시 배포하면, 네이버가 그 번호를 보내는 네이버 계정으로 로그인할 때 매니저 계정으로 들어갑니다(그 네이버 계정이 다른 회원에 연결되어 있었으면 그 연결은 풀리고 매니저에 연결됨). 백업으로 `https://zhstrade.pages.dev/manager-login`(사이트 어디에도 링크 없음)에서 아이디 `sosirusok`와 비밀번호로도 로그인합니다. 매니저 메뉴 → 설정 → **네이버 계정 연결**도 그대로 됩니다.
- **만 14세 미만**: 네이버가 보낸 출생연도로 (올해 − 출생연도) < 14인 새 네이버 계정은 가입 마무리로 가지 않고 `만 14세 미만은 가입할 수 없습니다.`가 표시됩니다. 가입 마무리의 `만 14세 이상입니다` 체크도 그대로 받습니다.
- **회원 정보**: 매니저 메뉴 → **회원 정보** 탭에서 탈퇴하지 않은 모든 회원의 닉네임, 회원이름, 연락처 이메일, 출생연도, 휴대전화번호를 봅니다(닉네임 검색). 같은 탭의 **관리자 열람 권한**에서 관리자 등급 회원마다 볼 항목을 체크하면, 그 회원의 내 메뉴에 **회원 정보**(`/member-info`)가 생기고 체크한 항목만 보입니다. 체크를 모두 풀거나 관리자 등급이 끝나면 바로 볼 수 없습니다. 회원은 프로필 수정의 **네이버 회원 정보**에서 자기 정보를 봅니다. 그 밖의 화면과 API(프로필, 글, 목록, 채팅, 검색)는 이 값을 보내지 않고, 탈퇴하면 지워집니다.
- **같은 휴대전화번호**: 활동 중인 회원과 같은 번호의 다른 네이버 계정은 가입할 수 없습니다(`같은 휴대전화번호로 가입된 계정이 있습니다.`). 이 기능 전에 가입한 회원은 다음 네이버 로그인 때 번호 해시가 저장되고, 탈퇴하면 지워집니다. 네이버가 번호를 보내지 않으면(제공 정보에 휴대전화번호가 없을 때) 확인 없이 가입됩니다. 기존 계정 연결도 같은 번호의 다른 회원이 있으면 되지 않습니다. 해시 키 `PHONE_HASH_KEY`는 Worker 비밀값으로 한 번 넣고 바꾸지 않습니다(바꾸면 저장된 해시가 맞지 않고 암호화한 회원 정보도 다음 로그인 전까지 열리지 않음). 키가 없으면 번호 확인은 꺼지고 회원 정보도 저장되지 않으며 Worker 로그에 경고가 남습니다.
- **개인정보 처리방침**: `/privacy` (화면 아래 링크, 가입 마무리의 이용 규칙). 코드가 실제로 수집·보관하는 항목만 적었으므로, 수집 항목이나 탈퇴 처리를 바꾸면 `src/pages/Privacy.tsx`도 함께 고칩니다.
- 네이버 접근 토큰은 저장하지 않습니다. 로그인 중의 확인 값은 10~30분짜리 HttpOnly 쿠키(Client Secret으로 서명, 회원 정보는 암호화된 값으로만)에만 둡니다.
- **계정 정리 (0066)**: 네이버가 연결되지 않은 계정(예전 아이디 계정, 탈퇴 회원)은 글·채팅·댓글·제시·거래 기록·알림 등과 함께 모두 지워지고, 매니저 계정은 아이디·비밀번호·역할만 남기고 내용(글, 채팅, 소개, 사진, 네이버 연결)이 비워집니다. 공지와 설정은 남습니다. 지운 사진 중 KV에 있던 것은 매일 정리 때 지워집니다.

### 새 주소 (zhstrade.pages.dev)

- **구조**: Cloudflare Pages 프로젝트 `zhstrade`가 화면 파일을 직접 내보내고, `/api/*` 요청만 서비스 바인딩으로 지금의 Worker(`zombiego-market`)에 넘깁니다. 서버, 데이터베이스, 사진, 예약 작업(자동 끌올·알림·정리)은 그대로입니다. 프로젝트는 배포가 처음 한 번 만들고, 지우거나 다시 만들지 않습니다.
- **이전 주소**: 같은 배포에서 새 주소가 첫 화면, API(방문자 주소 전달 포함), 하위 경로 확인을 통과한 뒤에만 `workers.dev` 주소가 새 주소로 자동 이동(301)합니다. 확인을 통과하지 못하면 배포는 경고(`새 주소 미적용`)만 남기고 초록색으로 끝나며, 사이트는 이전 주소에서 그대로 열립니다. API(`/api/*`)는 이전 주소에서도 계속 응답하므로 열려 있던 화면과 휴대폰 알림도 그대로 동작합니다.
- **다시 로그인**: 로그인은 주소마다 따로 저장되므로, 회원은 새 주소에서 한 번 더 로그인합니다. 네이버 Callback URL이 새 주소로 등록되어 있으므로 네이버 로그인은 새 주소에서만 됩니다.
- **토큰 권한**: API 토큰에 `Account` · `Cloudflare Pages` · `Edit`이 필요합니다(**Edit Cloudflare Workers** 템플릿에는 없음). 이미 만든 토큰이면 <https://dash.cloudflare.com/profile/api-tokens>에서 그 토큰의 **Edit** → 권한 한 줄 추가 → **Update token** 후 Actions에서 다시 실행하면 됩니다(토큰 값은 바뀌지 않음).
- **요금**: 화면 파일(HTML, JS, 아이콘, 글꼴) 요청은 Pages가 무료·무제한으로 처리하고 함수도 실행하지 않습니다. `/api/*` 요청만 Pages 함수 한 번으로 계산되고, Worker로 넘기는 서비스 바인딩 호출은 추가 요청으로 계산되지 않으므로 하루 요청 사용량(무료 10만 건)은 지금과 거의 같습니다. 다른 비용도 바뀌지 않습니다.
- **설정**: 다른 프로젝트 이름은 저장소 Variables의 `PAGES_PROJECT`에 넣습니다. `USE_PAGES`=`false`이면 새 주소 단계를 건너뛰고, 그 배포부터 이전 주소가 다시 사이트를 직접 보여 줍니다(Pages 프로젝트는 지우지 않음).

## 운영 메모

- **새 래더 시즌**: 매니저 관리 → 설정에서 현재 시즌을 올리면 글쓰기·검색의 시즌 선택지가 늘어납니다.
- **등급 입금 안내**: 매니저 관리 → 설정의 문구가 인증·등급 신청 창에 그대로 표시됩니다.
- **6개월 등급**: 지급일부터 6개월 뒤 자동으로 내려가며, 영구 등급이 있으면 그 등급으로 돌아갑니다. 같은 등급을 기간 중에 다시 지급하면 남은 기간 뒤로 6개월이 이어집니다.
- **자동 정리**: 매일 03:17(한국 시각)에 만료된 로그인과, 글·채팅·임시저장 어디에도 쓰이지 않은 채 하루가 지난 사진을 지웁니다.
- **사진 용량(R2 없이 D1에 저장할 때)**: 한 장 1.4MB, 회원 1인 30MB, 사이트 전체 300MB까지입니다. 무료 D1 용량(500MB)이 사진으로 가득 차 로그인·글쓰기가 멈추는 일을 막기 위한 제한입니다.
- **관리자 등급**은 표시용 등급입니다. 매니저 권한(신청 처리, 신고, 숨김)은 매니저 계정에만 있습니다.
- 무료 요금제 기준으로 요청당 CPU 시간이 짧아 비밀번호 해시는 PBKDF2-SHA256 20,000회로 저장하며, 해시에 반복 횟수를 함께 기록합니다.

## 로컬 개발

Node.js 22.13 이상과 pnpm(`packageManager`에 지정된 버전)을 사용합니다.

```bash
pnpm install --frozen-lockfile
echo 'MANAGER_PASSWORD=원하는-비밀번호' > .dev.vars   # 로컬 매니저 계정용, Git에 올라가지 않음
pnpm db:migrate:local
pnpm dev
```

로컬에서는 D1과 R2를 흉내 낸 저장소(`.wrangler/state`)를 쓰므로 Cloudflare 계정이 없어도 됩니다.
로컬에서 네이버 없이 회원을 만들려면 `.dev.vars`에 `LEGACY_AUTH_TEST=on`을 넣습니다. 예전 가입·로그인 API(`/api/auth/register`, `/api/auth/login`)가 로컬 주소(127.0.0.1, localhost)에서만 열립니다(화면에는 없음). 매니저는 `/manager-login`을 씁니다.

검사:

```bash
pnpm typecheck
pnpm build
pnpm test      # 로컬 서버를 띄워 API 검증 5종(거래, 인증·등급, 동시 처리·검색 등 수정 사항, R2 없는 사진 저장, 매일 정리)을 실행
```

검증은 네이버를 부르지 않습니다. `tests/verify-naver.mjs`는 로컬 흉내 서버(`tests/fixtures/naver-mock.mjs`)로 토큰·프로필 요청을 받고(`TEST_HOOKS=on`, 로컬 요청일 때만 `NAVER_AUTH_BASE`/`NAVER_API_BASE` 적용), 나머지 검증은 로컬 요청에만 예전 가입·로그인을 남기는 테스트 전용 값 `LEGACY_AUTH_TEST=on`으로 회원을 만듭니다. 배포에는 두 값 모두 들어가지 않습니다.

## 구조

| 경로 | 역할 |
| --- | --- |
| `src/` | 화면(React). `pages/`는 화면별, `components/`는 공용 부품, `styles/`는 디자인 토큰과 스타일 |
| `worker/` | API 서버(Cloudflare Worker). 게시글, 사진, 채팅, 인증·등급 신청, 매니저 기능 |
| `shared/` | 화면과 서버가 함께 쓰는 거래 규칙(티어·시즌, 분류, 우대 스킨, 등급·인증 정의) |
| `migrations/` | D1 테이블 변경 기록(추가만 함) |
| `tests/`, `scripts/test-local.mjs` | 로컬 API 검증 |
| `scripts/pages-out.mjs` | 새 주소(Pages)에 올릴 폴더(`_worker.js`, `_routes.json`, 서비스 바인딩 설정)와 이전 주소의 자동 이동 파일(`_redirects`) 생성 |
| `public/icons/` | Microsoft Fluent Emoji 컬러 아이콘(MIT, `LICENSE.md` 포함) |
| `.github/workflows/` | CI(타입 검사·빌드·검증)와 Cloudflare 자동 배포 |
| `docs/research.md` | 거래 용어·우대 스킨·배포 제약 조사 근거 |

글꼴은 Pretendard(SIL OFL)를 사이트에 포함해 배포합니다.
